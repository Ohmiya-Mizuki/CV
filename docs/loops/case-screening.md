# ループ仕様: 届いた受託案件の選別と経歴書の書き換え案

動かし方は [case-screening/README.md](../../case-screening/README.md)。

| 項目 | 決まり |
| --- | --- |
| 目的 | 届いた受託案件を、経歴の事実と照らして「合う点・足りない点・面談で確かめる事項」付きで選別し、選んだ案件に合わせた経歴書の書き方の案を出す |
| 名義 | 個人事業 |
| 起動 | Mac mini の LaunchAgent `local.automation-infra.case-screening`、毎朝 6:40 |
| 入力 | 案件の紹介が届く経路（設定の `sources`。いまは法人の Gmail をコネクタで、個人事業の Gmail を読み取りだけの認証で）の、経路ごとの検索に合うスレッドのうち、前回の成功から後のもの。本人が選んだ印のラベル（`selectLabel`）が付いたスレッド。スキルシート（事実の正本）。CV の `origin/main` の `README.md` |
| 成果の置き場 | 報告（案件の中身つき）は、本人だけが見る Mac mini の手元（`~/mac-mini-ci/case-screening/reports/`）。法人の Drive には置かない。書き換え案は、CV の下書きの PR |
| 知らせ | life の案内の issue（`inbox:output`・`owner:freelance`）へ件数と PR の URL だけのコメント。朝の1通が `#inbox-freelance` へ件数とリンクだけを届ける。新しい案件がない回は書かない |
| 段階 | P1（下書きまで）。応募・返信・面談の申し込みはしない。PR は下書きで、マージは本人 |
| 止める変数 | 設定の `enabled`（既定は止める）。外へ出すのは `dryRun` が `false` のときだけ |
| 外へ出す前の検査（コード） | `scripts/case-screening.ts`: 結果の形、検索で見つかったスレッドか、合う点と書き換えの根拠がスキルシートにそのまま含まれるか、確かめる事項があるか、根拠のない「主導」、コミット数のアピール、作業メモのような文言、公開の文に会社名・紹介元・案件名・単価・URL がないか。どれかに当たれば、その回は何も出さずに失敗にする |
| 1回の上限 | 読むスレッドは50件まで（超えたら読まずに空で終える）。経歴書の案は1回に1件 |
| 二重の防止 | 報告済みのスレッド ID（`seen.txt`）と、案を出したスレッド ID（`tailored.txt`）を残す。前の実行が残っていれば見送る |
| 見張り | automation-ops の Mac mini の定期のジョブの見張りが、`runs.log` の更新時刻（31時間）と LaunchAgent の最後の終了コードを読む。Healthchecks の check は増やさない |
| 失敗の扱い | 失敗の回は起点を進めず、次の回が同じ起点から読む。終了コード 1 |
| 外れの数え方 | 本人が報告を見て「判定が違う」と言ったものと、閉じた下書きの PR を数える。dry-run の間に、報告と Gmail を見比べて取りこぼし・誤りを数え、`dryRun` を外すか決める |

## 本人が決めること

- 対象にする紹介元（経路ごとの `query`）。2026-11-18の時点で未定
- 個人事業の Gmail の読み取りだけの認証を用意するか（README の「個人事業の Gmail」）
- `enabled` と `dryRun` を外す時期
