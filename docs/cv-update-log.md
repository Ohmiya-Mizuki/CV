# 業務経歴書の月次更新ログ

月次更新ループ（`.claude/skills/cv-monthly-update/SKILL.md`）の実施記録。追記型で、既存のエントリは書き換えない。
最終エントリの「調査期間の終わり」が、次回の調査開始日になる。

このリポジトリは公開されているため、ここには公開してよい要約だけを書く。根拠の詳細と本人への質問は `.local/cv-update/`（gitignore済み）に置く。

## 2026-10-12 ループ導入

- 調査期間の終わり: 2026-09-03（導入時点の README.md「最終更新日」。初回は 2026-09-03 以降の活動を調べる）
- 内容: 月次更新ループを導入。毎月1日 10:00 に Claude デスクトップアプリの定期タスク `cv-monthly-update` から起動する。
- 設計判断:
  - 実行場所: 根拠になる案件リポジトリは手元のMacにしかなく、クライアントのコードをクラウドや別ホストへ持ち出さないため、ローカルの定期タスクで動かす。GitHub Actions・クラウド実行・Mac mini は使わない。
  - 出力: Draft PR まで。マージは本人が行う。
  - 公開範囲: 根拠と質問は非公開メモへ分け、PR本文には要約だけを書く。
  - レビュー: 差分と根拠だけを渡した別エージェントが、誇張と公開してはいけない情報を確認する。
  - 端末依存の設定: 根拠を探す場所はディレクトリ構成が端末ごとに違い、公開リポジトリにも載せたくないため、`.claude/settings.local.json`（gitignore済み）の `env` で渡す。CVリポジトリ内のパスは `git rev-parse --show-toplevel` からの相対で決める。シェルの `export` はデスクトップアプリの定期タスクに渡らない可能性があるため使わない。
  - automation-harness（`.loopguardrails/`）は導入しない。スクリプトは根拠のリポジトリを列挙する1本だけで、submodule・lefthook を入れるほどではないため、loop-review の6観点で設計した結果だけをここに残す。
- loop-review の6観点:
  - Automations: ○ 月次の定期タスク
  - Worktrees: ○ `../CV-worktrees/cv-update-YYYY-MM` で作業し、手元のブランチを汚さない
  - Skills: ○ `cv-monthly-update`
  - Plugins/connectors: △ 根拠はローカルの git log と `gh` のみ。案件のPR・チケットは見ない（関与の確認は質問で補う）
  - Sub-agents: ○ 手順8のレビュー
  - Memory: ○ このログ（公開）と `.local/cv-update/`（非公開）

## 2026-10-18 提出用 Word の作成を手順に追加

- 調査期間の終わり: 2026-10-13（変更なし。手順の変更のみ）
- 内容: エージェントへの提出が Word だったため、README.md から Word を作る `scripts/build-docx.ts` と雛形 `templates/reference.docx` を追加し、手順11として組み込んだ。
- 設計判断:
  - 正本は README.md の1つに保つ。Word は生成物として `.local/cv/` に出し、Git に入れない。
  - 見た目（A4・游ゴシック・段落の間隔）は雛形で固定し、生成スクリプトで再現できるようにした。
  - ページ数の目安は LibreOffice で数える。`--headless` では Mac のフォントを使えず日本語の幅を数えられないため、macOS の描画方式で変換する。
  - Word で 8 ページになったため、案件の基本項目を表から3行の表記に変え、表の列幅と段落の間隔を調整して 6 ページにした。さらに本人の選択で、AI エージェントデモ基盤とアクティビティ予約システムの成果を 5〜6 項目に絞り、文字を 9.5pt・余白を 15mm に詰めて 5 ページにした。
  - 4 ページにするには動画配信サービスの記述かスキル表を大きく削る必要があったため、本人の判断で 5 ページを上限とした。手順11の基準も 5 ページにした。
  - スクリプトは本人の希望で Python と sh から TypeScript に置き換え、`node:test` のテストを追加した（列挙スクリプト `list-evidence-repos.sh` のテストを含む）。依存パッケージは増やさず、docx の展開と圧縮は unzip / zip を使う。
