## 職務要約

2020 年 10 月の大学在学中から業務委託（フリーランス）として 6 年間、Web アプリケーション開発に継続して参画。Next.js / TypeScript を中心としたフロントエンドを土台に、Laravel のバックエンド、Terraform による AWS / Google Cloud の IaC と CI/CD まで担当する。直近は、Claude Code などの AI エージェントが安全に開発を回すための仕組み（ガードレール、静的解析の独自ルール、CI の品質ゲート）の設計・導入を軸に、テスト実行の約 3 倍高速化やデプロイ時間の約 17% 短縮を実現した。36 か月参画した動画配信サービスでは、参画 3 か月でテックリードに昇進し、単価は契約当初の 1.7 倍になった。

---

## 得意なこと

- **AI エージェント向けのガードレール設計**
  AI が実際に起こした事故から逆算した禁止・確認ルール、フックの迂回検知、ガードレール設定そのものの編集防止（AI エージェントデモ基盤／アクティビティ予約システム）
- **静的解析と lint による品質ゲートの機械化**
  PHPStan の層間依存を検知する独自ルール、ESLint の 2 ルールの error 化による既存違反約 200 件の解消、ルール無効化時の理由の必須化（アクティビティ予約システム／AI エージェントデモ基盤／ファンクラブ）
- **CI/CD と開発基盤の高速化**
  テスト実行を約 3 倍高速化、デプロイ時間を約 17% 短縮、PHPStan のテスト解析を「60 秒でタイムアウト」から「11 秒で完了」に（AI エージェントデモ基盤／アクティビティ予約システム）
- **本番を守る構成とセキュリティ**
  環境ごとの設定の取り違えを防ぐ構成、認可の不備の修正、秘密情報を無停止で入れ替える仕組み（アクティビティ予約システム／AI エージェントデモ基盤／ファンクラブ）
- **TypeScript のフロントエンド開発（React / Next.js・Svelte、5 年）**
  大規模な動画配信サービスの新規開発に 36 か月、航空券予約の複雑な予約ロジック（動画配信サービス／航空券予約システム）

### BtoB 向け AI エージェントデモ基盤の開発

| 項目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 期間     | 2026 年 6 月 〜 現在（並行稼働）                             |
| 参画形態 | 業務委託                                                     |
| 役割     | 基盤エンジニア（設計・実装・インフラ・CI）                   |
| 体制     | 3 名                                                         |
| 主な技術 | TypeScript / Next.js / Anthropic Claude API / Google Cloud / Claude Code |

Anthropic Claude API を中核に、複数の AI ペルソナが役割分担して動くエージェントアプリ。Slack・LINE・Discord などのマルチチャネルでボット連携する。

- AI エージェントが実際に起こした事故（重複 PR の量産、意図しない自動マージなど）から逆算して、Claude Code のガードレール（危険操作の禁止・確認ルール、フックの迂回検知）を設計
- ESLint の非同期処理に関する 2 ルールを error 化し、既存の違反約 200 件を解消。あわせて抑制コメント 29 箇所を撤廃し、CI で機械的に検知
- テスト実行を約 3 倍高速化（10.17 秒 → 3.31 秒、全 1,088 テストが通る状態のまま）
- CI の手順を並列化し、デプロイ時間を約 17% 短縮（約 463 秒 → 約 380 秒）
- GitHub Secrets 44 件を Secret Manager の参照へ移行
- 依存パッケージを見直し、node_modules を約 250MB 削減
- 認可の不備を見つけて修正し、テストを追加

### 航空会社マイレージ会員向けアクティビティ予約システムの改修・基盤刷新

| 項目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 期間     | 2025 年 11 月 〜 現在                                        |
| 参画形態 | 開発会社経由の業務委託（二次請け）                           |
| 役割     | フルスタックエンジニア（バックエンド・インフラ中心）         |
| 体制     | 発注元 PM 1 名（非エンジニア）＋エンジニア 2〜3 名           |
| 主な技術 | PHP / Laravel 11 / PHPStan（level 9）/ MySQL / AWS（ECS・RDS・CodePipeline・CodeBuild）/ Terraform / Claude Code |

旅行会社（OTA）と航空会社のマイレージプログラムを連携し、会員がマイル償還で現地アクティビティを予約できるプラットフォーム。トラベラー向けフロント・社内向け管理画面・予約取り込みバッチで構成する。テックリードを置かないフラットなチームで、技術方針をエンジニア間で決め、設計・コードレビュー・マージを分担している。

- PHP 7.4 から Laravel 11 への段階的な移行
- PHPStan に層間の依存違反を検知する独自ルールを追加。エラー文を AI エージェント向けに整え、見つかった既存の違反も修正
- 型エラーの抑制コメント（phpstan-ignore）を一度全廃したうえで、baseline の削減を継続しながら件数の増加を検知する CI を導入
- Claude Code の開発基盤を整備（フックの迂回を防ぐルール、@claude で起動する Claude Code Action の CI）
- PHPStan のテスト解析を「60 秒でタイムアウト」から「11 秒で完了」に改善（巨大なテストファイルを 7 クラスに分割）
- CI の lint・静的解析を約 34 秒短縮し、main で失敗していたユニットテスト 26 件を修正
- 環境ごとの設定の取り違えが起きない構成に改め、本番の接続先を保護
- Terraform の tfstate をリモートバックエンドへ移行し、本番の CD パイプラインを構築。MySQL 5.7 から 8.4 への更新では、ローカル・ステージング環境の移行と互換対応を担当
- クーポン機能を設計書の作成から本番投入まで担当

### サブスクリプション型動画配信サービスの大規模新規開発

| 項目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 期間     | 2021 年 12 月 〜 2024 年 11 月（36 か月）                    |
| 参画形態 | 業務委託                                                     |
| 役割     | テックリード兼 3 名マイクロチームのマネジメント（参画時はプログラマー、3 か月後にテックリードへ昇進） |
| 体制     | 約 20 名                                                     |
| 主な技術 | TypeScript / React / Next.js / Apollo Client / GraphQL / Emotion / Jest / React Testing Library / GitHub Actions |

TV・ゲーム機などの特殊デバイス向けアプリのフロントエンド開発。AI による開発支援が普及する前に、設計・実装・レビューを自分の手で積み重ねた現場。

**評価**: 参画 3 か月でテックリードに昇進し、単価は契約当初の 1.7 倍になった。PM と PL からの指名でチーム内勉強会を主催した。

#### 設計レビューの導入による品質の底上げ

実装者のコンポーネント設計スキルによって画面の品質がばらつき、保守性が下がっていた。実装に着手する前の設計レビューを提案し、レビュー観点の策定からチームの運用に乗せるまでを一人称で担当した。実装の手戻りとバグの発生が減り、各実装者の設計力も上がった。

#### リリース直前の品質担保

開発初期は 1 画面を 1 人が担当し、画面ごとの設計の質が担当者に依存していた。その負債がリリース直前に顕在化し、あるバグを直すと別のバグが出る状態だった。期限の範囲で根本の設計を見直しながらデバッグを進め、複数のバグをまとめて解消し、リリース時点で対応必須としていたバグを全件解消した。

#### 「1 作業者」で留まらない動き方

手が空いたときはチームで優先度の高いタスクを周囲と確認して取りに行き、プロダクトコード全体から PM・PL も把握していない技術的負債や生産性の改善点を見つけて issue 化した。バグを生みそうな UI はデザイナーと仕様を調整し、型安全な実装のために BFF のデータ型の変更を依頼するなど、ステークホルダーとの調整も担った。

#### チームの育成と橋渡し

コードレビューでのフィードバックと週次の勉強会で、メンバーの技術力を底上げした。日本語での言語化に苦労するメンバーもいたため、開発者から管理職への報告で情報の補足や状況の整理を行い、コミュニケーションエラーを減らした。

**主な担当**

- ディレクトリ構造のリアーキテクチャ、コンポーネント・hooks の共通化と分離
- テスト設計と自動テストの導入（Jest + React Testing Library）
- GitHub Actions による CI/CD ワークフローの作成と運用改善
- Apollo Client + GraphQL による offset / cursor ページネーションの新規実装
- 作品詳細画面の仕様確認・UI コンポーネント設計・API 繋ぎ込み
- アプリケーションのパフォーマンス改善と、特殊デバイスの実機不具合の調整
